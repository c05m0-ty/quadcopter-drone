## 4. 系统时钟和外设基础配置

系统使用 8 MHz HSE，通过 PLL 产生 216 MHz 主频：

- PLLM = 8
- PLLN = 432
- PLLP = 2
- 主频 = 8 MHz / 8 × 432 / 2 = 216 MHz

USB 48 MHz 使用 PLLSAI：

- PLLSAIN = 384
- PLLSAIP = 8

系统启用了：

- Over-Drive
- 电压等级 Scale 1
- Flash 7 等待周期
- MemManage、BusFault、UsageFault

异常入口放在独立 `fault_handlers.s` 中，异常时会通过 LED 输出故障 PC 低 16 位，便于没有 ST-Link 时定位问题。

## 5. USB CDC 虚拟串口

### 5.1 实现

USB 设备被配置为 STM32 CDC 虚拟串口：

- VID：`0x0483`
- PID：`0x5740`
- 固定序列号：`JHEF722PRO01`
- Windows 枚举为 `USB 串行设备`

USB 软件栈包括：

- STM32 USB Device Core
- CDC 类
- 本地 USB 板级配置和描述符
- USB 接收环形缓冲
- 分块发送接口

### 5.2 关键故障与修复

最初端口出现后很快变为 Code 10，并返回 `STATUS_IO_TIMEOUT`。

通过异常 PC 定位和反汇编，发现问题发生在序列号描述符生成阶段：

- 原实现读取 `UID_BASE`
- 实板在该访问路径上触发 BusFault
- USB 枚举无法完整完成

修复方式：

- 不再在描述符回调中访问芯片 UID
- 使用固定序列号 `JHEF722PRO01`

随后 Windows 设备状态变为 `OK`，虚拟串口可稳定打开和收发。

### 5.3 USB 多包发送

测试中发现超过 64 字节的数据在第一个完整 USB 包处被截断。

处理方式：

- CDC 单次软件分块大小由 64 字节调整为 63 字节
- 后续业务输出拆成较短消息，避免跨越完整包边界

### 5.4 当前 USB 行为

- USB 连接稳定后等待约 5 秒
- 然后启动 Cube 数据流
- 串口接收字符 `z` 或 `Z` 时，将当前姿态重新设为零点

## 6. LSM6DSK320X 陀螺仪和加速度计

### 6.1 芯片识别

读取 `WHO_AM_I` 寄存器 `0x0F`：

- 芯片 ID：`0x75`
- 对应型号：LSM6DSK320X

Betaflight LSM6DSV 驱动中同样定义：

```c
#define LSM6DSK320X_WHO_AM_I_CONST (0x75)
```

### 6.2 SPI 配置

- SPI1 主机模式
- 8 位数据
- MSB First
- SPI Mode 3
- 软件片选
- SPI 时钟约 `844 kHz`
- PA4 空闲高电平

曾测试：

| 配置 | WHO_AM_I |
|---|---:|
| Mode 3 / 3.375 MHz | 0xFF |
| Mode 3 / 844 kHz | 0x75 |
| Mode 0 / 3.375 MHz | 0x75 |
| Mode 0 / 844 kHz | 0x75 |

最终采用更符合 LSM6 系列访问习惯的 Mode 3 低速配置。

### 6.3 传感器量程和输出率

当前配置：

- 陀螺仪：±2000 dps
- 加速度计：±16 g
- 陀螺仪 ODR：1 kHz
- 加速度计 ODR：1 kHz
- 陀螺仪 LPF1：启用
- 加速度计 LPF2：启用
- BDU：启用
- 地址自动递增：启用

换算关系：

- 陀螺仪：`0.07 dps/LSB`
- 加速度计：`1 g = 2048 LSB`

### 6.4 数据就绪中断

- 传感器 INT1 配置为 FIFO 阈值/溢出中断
- PC3 配置为上升沿 EXTI
- 中断中只设置数据就绪标志
- 中断不执行 SPI 或复杂解析

### 6.5 FIFO

当前 FIFO 配置：

- Stream/Continuous 模式
- 陀螺仪和加速度计均进入 FIFO
- FIFO 水位：16 条记录
- 每条普通传感器记录：1 字节标签 + 6 字节数据
- 记录类型包括陀螺仪、加速度计、温度、时间戳和配置变更

FIFO 在 USB 连接并等待 5 秒后才启用。早期版本在开机时立即启用，导致等待期间 FIFO 溢出，Cube 数据冻结；该问题已修复。

### 6.6 DMA

SPI1 DMA 映射：

| 方向 | DMA |
|---|---|
| SPI1 RX | DMA2 Stream0，Channel3 |
| SPI1 TX | DMA2 Stream3，Channel3 |

DMA 特性：

- Normal 模式
- 字节宽度
- 内存地址递增、外设地址固定
- 高优先级
- 32 字节对齐缓冲区
- D-Cache clean/invalidate
- 一次最多读取 32 条 FIFO 记录
- DMA 完成或错误回调中释放 PA4
- 超过 5 ms 未完成时自动 Abort

### 6.7 数据链路

```text
1 kHz 传感器采样
    ↓
传感器 FIFO
    ↓
PC3 FIFO 阈值中断
    ↓
读取 FIFO 记录数量
    ↓
SPI1 DMA 批量读取
    ↓
解析标签和六轴数据
    ↓
逐样本姿态积分
    ↓
USB 20 Hz 输出
```

## 7. 姿态计算和 VOFA+ Cube

### 7.1 当前姿态算法

当前使用简化互补滤波：

- 横滚和俯仰：陀螺仪积分 + 加速度计重力修正
- 偏航：陀螺仪 Z 轴积分
- 没有磁力计或 GPS 航向修正
- 输出为欧拉角

加速度计修正只在加速度模长有效时启用，避免零值或异常样本把姿态拉向错误方向。

### 7.2 VOFA+ 数据格式

数据引擎：

```text
FireWater
```

输出通道：

```text
roll,pitch,yaw
```

参数：

- 单位：弧度
- 频率：约 20 Hz
- Cube 使用欧拉角模式
- X 绑定 channel 0
- Y 绑定 channel 1
- Z 绑定 channel 2
- Scalar 不绑定

### 7.3 姿态归零

- 第一次取得姿态样本时自动记录零点
- 运行中发送 `z` 或 `Z` 重新记录当前姿态为零点
- 归零同时作用于横滚、俯仰和偏航

### 7.4 偏航误差说明

快速多方向甩动后，横滚和俯仰能逐渐回到正确角度，但偏航会出现明显累计误差。

主要原因：

1. 没有磁力计，偏航没有绝对参考
2. 直接把陀螺仪 Z 轴角速度当世界坐标偏航角速度
3. 大幅横滚/俯仰时三轴角速度存在耦合
4. 快速运动可能超过 ±2000 dps 量程
5. 陀螺仪零偏会持续积分

发送 `z` 可以在板子回到期望方向后手动消除累计偏航。

## 9. 当前限制

1. 当前是实验和硬件验证固件，不是可直接飞行的完整飞控固件。
2. 姿态输出为欧拉角，尚未实现 Mahony、Madgwick 或完整四元数 EKF。
3. 没有磁力计，偏航不是绝对航向，剧烈运动后会漂移。
4. 陀螺仪目前为 1 kHz 和约 844 kHz SPI，尚未启用 8 kHz 或更高 SPI 时钟。
5. PB8 的 `GYRO_CLKIN` 尚未配置；传感器当前可不依赖该引脚工作。
6. 尚未实现以下板载外设驱动：
   - UART1～UART5
   - CRSF 接收机协议
   - DPS310 气压计
   - MAX7456 模拟 OSD
   - 16 MB SPI Flash 和黑匣子
   - 电池电压、电流和 RSSI ADC
   - DShot 电机输出
   - 蜂鸣器
   - LED Strip / WS2812
   - PINIO 功能
7. 当前没有接收机、GPS 和电机控制逻辑，不能用于实际飞行。

## 11. 结论

本次工作已经完成 JHEF722PRO 的 USB CDC、LSM6DSK320X SPI 驱动、数据就绪中断、1 kHz FIFO、SPI1 DMA 和基础姿态输出链路。

USB 的主要根因是描述符读取 UID 时触发 BusFault；修复后设备可稳定工作。

陀螺仪通过 `WHO_AM_I = 0x75` 正确识别，FIFO 与 DMA 批量读取已经通过实板验证。

目前姿态数据能够驱动 VOFA+ Cube，并支持运行时归零，但偏航仍然受无磁力计和积分误差限制。

该工程目前适合作为飞控硬件验证和后续外设驱动开发的基础，不应视为完整可飞行固件。
